# Generated Hypothesis Test Scripts

This directory contains Python scripts automatically generated by Claude AI to test specific hypotheses.

## Purpose

When no existing diagnostic tool can test a hypothesis, Claude can write a custom Python script. These scripts are saved here for:

1. **Traceability** - See exactly what analysis was performed
2. **Reusability** - Successful scripts can be promoted to permanent tools
3. **Debugging** - If a test fails, the script can be examined and fixed

## Script Format

Each script contains:
- Metadata header (hypothesis name, timestamp, description)
- A `test_hypothesis()` function with this signature:

```python
def test_hypothesis(param_matrix, y_outputs, screening_data, config):
    """
    Args:
        param_matrix: np.ndarray (n_cases, n_params) - Morris parameter values
        y_outputs: dict - Output variables keyed by name
        screening_data: dict - Screening results from Phase 2
        config: dict - Configuration (param_names, pft_ids, use_case_dir)

    Returns:
        dict with:
            - supported: bool
            - confidence: float (0-1)
            - evidence: dict
            - insights: list
    """
```

## Naming Convention

```
{script_name}_{YYYYMMDD_HHMMSS}.py
```

Example: `test_p_cycling_efficiency_20260209_143022.py`

## Promoting Scripts to Permanent Inventory

If a generated script proves useful and is generic enough to be reused, you can promote it to the permanent diagnostic tools inventory.

### Step 1: Review the Script

After running Phase 3, review the generated scripts:
- Did the script produce useful insights?
- Is the analysis generic enough to apply to other calibrations?
- Does it follow the expected function signature?

### Step 2: List Available Scripts

```bash
python tools/promote_diagnostic_script.py --list
```

This shows all generated scripts with their metadata.

### Step 3: Dry Run (Preview)

```bash
python tools/promote_diagnostic_script.py --script test_p_cycling.py --dry-run
```

This shows what changes would be made without executing them.

### Step 4: Promote the Script

```bash
# With auto-detected settings
python tools/promote_diagnostic_script.py --script test_p_cycling.py

# With custom settings
python tools/promote_diagnostic_script.py --script test_p_cycling.py \
    --tool-name analyze_p_cycling_efficiency \
    --category "Nutrient Pool Analysis" \
    --description "Analyze P cycling efficiency across ensemble" \
    --use-when "Suspect P limitation or cycling issues"
```

### What Promotion Does

1. **Copies** the script to `phases/phase3_diagnosis/`
2. **Updates** `DIAGNOSTIC_TOOLS_INVENTORY` in `reasoning.py`
3. **Preserves** the original in `generated/` for reference

### Available Categories

- Parameter Analysis
- PFT Limitation Analysis
- Mortality & Collapse Analysis
- Nutrient Pool Analysis
- Target Comparison

## Cleanup

Old scripts can be safely deleted after review. They are kept for reference but are not required for workflow operation.

To clean up old scripts:
```bash
# Remove scripts older than 30 days
find phases/phase3_diagnosis/generated -name "*.py" -mtime +30 -delete
```

## Security Note

These scripts are generated by AI and executed dynamically. They are saved before execution so they can be reviewed if issues occur. Always review promoted scripts before committing them to the repository.
