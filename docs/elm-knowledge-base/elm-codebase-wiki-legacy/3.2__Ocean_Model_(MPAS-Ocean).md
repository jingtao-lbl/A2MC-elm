## Purpose and Scope

MPAS-Ocean is E3SM's ocean component, implementing a global ocean model on unstructured Voronoi meshes with variable resolution capabilities. This page documents MPAS-Ocean's structure, configuration, time integration schemes, and physical parameterizations. For information about the broader MPAS framework shared across ocean, sea ice, and atmosphere components, see [MPAS Framework Deep Dive](#7) . For coupling infrastructure details, see [Coupling Infrastructure](#4) . For child-level details on time integration schemes and ocean physics, see [Time Integration Schemes](#3.2.1) and [Ocean Physics](#3.2.2) .

## Registry.xml: Model Structure Definition

The Registry.xml file is the central configuration file that defines MPAS-Ocean's data structures, dimensions, namelist options, and I/O streams. It is parsed at build time to generate Fortran code for data structures and I/O operations.

### Dimension Definitions

MPAS-Ocean defines both mesh dimensions and vertical layer dimensions in Registry.xml:

| Dimension | Definition | Description | 
| --- | --- | --- |
| nCells | Runtime | Number of horizontal cell centers (Voronoi polygons) | 
| nEdges | Runtime | Number of edge midpoints connecting cells | 
| nVertices | Runtime | Number of vertices (dual grid cell centers) | 
| maxEdges | Runtime | Maximum edges per cell (typically 10) | 
| nVertLevels | config_vert_levels | Number of vertical levels | 
| nVertLevelsP1 | nVertLevels+1 | Vertical interfaces (levels + 1) | 


The vertical coordinate uses a hybrid sigma-z coordinate system. The number of vertical levels is specified via the namelist parameter `config_vert_levels` (typically 60-80 layers).

- `'split_explicit'`- Original split-explicit with forward-backward barotropic subcycling
- `'split_explicit_ab2'`- Split-explicit with Adams-Bashforth 2nd order barotropic
- `'RK4'`- 4th order Runge-Kutta (all modes explicit, no subcycling)
- `'split_implicit'`- Split-implicit with implicit barotropic solve

## Time Integration Schemes

MPAS-Ocean implements multiple time integration schemes optimized for different use cases. The split-explicit methods are most commonly used for production runs.

### Split-Explicit Time Integration

The split-explicit scheme ( [ocn_time_integration_split.F](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/ocn_time_integration_split.F) ) separates fast barotropic (2D) and slow baroclinic (3D) modes:

![SVG image](3.2__Ocean_Model_(MPAS-Ocean)__img-03.svg)

Key Parameters:

- `config_dt`: Baroclinic timestep (e.g., 30 minutes for 30km resolution)
- `config_btr_dt`: Barotropic sub-timestep (e.g., 75 seconds)
- `config_dt / config_btr_dt`Number of subcycles:


The split-explicit-ab2 variant ( `config_time_integrator='split_explicit_ab2'` ) uses Adams-Bashforth 2nd order for the barotropic mode, improving stability and allowing larger barotropic timesteps.

### Split-Implicit Time Integration

The split-implicit scheme ( [ocn_time_integration_si.F](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/ocn_time_integration_si.F) ) replaces the explicit barotropic subcycling with an implicit solve, allowing much larger timesteps and better stability for high-resolution meshes:

Advantages:

- Larger allowable timestep (not CFL-limited for barotropic mode)
- Better suited for very high resolution (< 10 km)
- Reduced computational cost for deep ocean regions


Configuration:

The implicit solve uses a preconditioned conjugate gradient method to solve the 2D elliptic problem for sea surface height.

Sources:  [components/mpas-ocean/src/mode_forward/mpas_ocn_time_integration_si.F 1-50](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/components/mpas-ocean/src/mode_forward/mpas_ocn_time_integration_si.F#L1-L50)

### RK4 Time Integration

The 4th-order Runge-Kutta scheme ( [ocn_time_integration_rk4.F](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/ocn_time_integration_rk4.F) ) treats all modes explicitly without mode splitting:

Use Cases:

- Idealized test cases
- Short simulations where accuracy is critical
- Verification and validation


Limitations:

- Computationally expensive (4 tendency evaluations per timestep)
- Smaller allowable timestep than split methods

## Physical Parameterizations

MPAS-Ocean includes parameterizations for sub-grid-scale processes that cannot be resolved explicitly.

### Mesoscale Eddy Parameterizations
Gent-McWilliams (GM) Bolus Transport
The GM parameterization ( [ocn_gm.F](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/ocn_gm.F) ) represents the effect of mesoscale eddies on tracer transport through a bolus velocity that advects tracers along isopycnal surfaces.

Available Closures (`config_GM_closure`):

| Closure | Description | Use Case | 
| --- | --- | --- |
| 'constant' | Constant κ_GM everywhere | Simple, computationally cheap | 
| 'N2_dependent' | Varies with stratification (N²) | Better representation of vertical structure | 
| 'Visbeck' | Spatially varying based on deformation radius | Regional variation | 
| 'EdenGreatbatch' | Energy-based with EKE evolution | Most sophisticated, physics-based | 


Key Parameters:

- `config_use_GM``.true.`: Enable GM ( for most grids)
- `config_GM_constant_kappa`: Bolus diffusivity (600-900 m²/s for 30km grids)
- `config_GM_horizontal_taper``'ramp'``'RossbyRadius'`: Reduce GM at high resolution ( or )


The horizontal taper is critical for variable resolution meshes. When `config_GM_horizontal_taper='ramp'` :

- `config_GM_horizontal_ramp_min`GM is reduced in regions finer than (e.g., 20 km)
- `config_GM_horizontal_ramp_max`GM is at full strength in regions coarser than (e.g., 30 km)
