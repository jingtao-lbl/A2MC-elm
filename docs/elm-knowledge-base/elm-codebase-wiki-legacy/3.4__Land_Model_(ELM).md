## Purpose and Scope

This page documents the E3SM Land Model (ELM), which simulates terrestrial biogeophysical and biogeochemical processes including water, energy, carbon, and nitrogen cycling. ELM serves as the land component (LND) in the E3SM coupled modeling system and exchanges fluxes with the atmosphere, river, and glacier components.

For information about the river routing component that receives runoff from ELM, see [Other Components](#3.5) . For details on land-atmosphere coupling and flux calculations, see [Flux Calculations and Fractional Coverage](#4.4) .

## Component Architecture

### Component Location and Interfaces

ELM resides in [components/elm/](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/components/elm/) and implements the standard CIME component interfaces defined in the driver. The land component is registered as `COMP_LND` with the component class `LND` in the driver configuration.

Component Interface Functions:

The driver interacts with ELM through MCT-based interface functions defined in [driver-mct/main/cime_comp_mod.F90 50-51](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/driver-mct/main/cime_comp_mod.F90#L50-L51) :

These functions handle:

- **`lnd_init_mct`**: Initializes the land model, reads namelists, sets up domain decomposition, and initializes biogeochemistry
- **`lnd_run_mct`**: Advances the land model by one coupling timestep
- **`lnd_final_mct`**: Finalizes the land model and writes restart files


Component Presence and Prognostic Flags:

The driver tracks whether land is active through flags in [driver-mct/main/cime_comp_mod.F90 400-415](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/driver-mct/main/cime_comp_mod.F90#L400-L415) :

- `lnd_present``.true.`: Set to when land component is included
- `lnd_prognostic``.true.`: Set to when land expects input from other components


### Directory Structure

ELM's code is organized under `components/elm/` with the following key subdirectories:

- `src/`: Fortran source code
- `bld/`: Build-time configuration and namelist generation scripts
- `cime_config/`: CIME integration scripts and XML configuration files
- `tools/`: Offline tools and utilities

![SVG image](3.4__Land_Model_(ELM)__img-02.svg)

### BGC Mode Details

SP (Satellite Phenology)

- Simplest configuration with prescribed leaf area index (LAI)
- No prognostic carbon or nitrogen cycling
- Used for atmosphere-only or basic land simulations
- `IELM``I.*ELM%SP`Compset pattern: or


CN (Carbon-Nitrogen)

- Soil decomposition with vertically-resolved biogeochemistry

CROP (Interactive Crops)

- Extends CN mode with agricultural management
- Includes planting, harvest, fertilization
- Multiple crop functional types

ECA (Explicit Carbon Allocation)

- Alternative carbon allocation scheme

RD (Reactive Transport/RDCTC)

ELM build configuration is minimal compared to atmosphere or ocean components. The land model is compiled as part of the overall E3SM build and does not require separate configure options like `CAM_CONFIG_OPTS` .

Build Location:

ELM is built in `$EXEROOT/lnd/obj` with libraries placed in `$EXEROOT/lib` .

Component-Specific Build Variables:

While ELM itself has minimal build-time configuration, related XML variables include:

- `LND_GRID`: Land grid resolution (typically matches atmosphere grid)

## Domain and Fractional Coverage

ELM's domain information and fractional coverage are crucial for proper coupling with other components.

Land Fractions  [driver-mct/main/cime_comp_mod.F90 273-280](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/driver-mct/main/cime_comp_mod.F90#L273-L280) :

The coupler maintains land fractions on multiple grids:

- `fractions_lx`: Land fractions on the land grid (cpl processes)
- `fractions_ax`: Land fractions on the atmosphere grid (cpl processes)


These fractions determine how land fluxes are weighted when merging with ocean and ice contributions to the atmosphere.

Fraction Types:

- `lfrac`: Total land fraction (including land ice)
- `ifrac`: Ice fraction (sea ice + land ice)
- `ofrac`: Ocean fraction
- `afrac`: Atmosphere fraction (typically 1.0)


Fraction Initialization:

Fractions are initialized during `seq_frac_init()` and updated during the run via `seq_frac_set()`  [driver-mct/main/cime_comp_mod.F90 137](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/driver-mct/main/cime_comp_mod.F90#L137-L137)

Grid Information:

Land grid dimensions are stored as [driver-mct/main/cime_comp_mod.F90 284](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/driver-mct/main/cime_comp_mod.F90#L284-L284) :

- `lnd_nx``lnd_ny`, : Number of cells in x and y directions
- Used for diagnostic output and validation

## Performance and Scalability

### PE Layout Configuration

Land model parallel decomposition is configured through PE layout variables in `env_mach_pes.xml` :

Key Variables:

- `NTASKS_LND`: Number of MPI tasks for land
- `NTHRDS_LND`: Number of OpenMP threads per task
- `ROOTPE_LND`: Starting MPI rank for land tasks
- `NINST_LND`: Number of land component instances (for ensemble runs)


Typical Configurations:

For standard resolution (ne30, f09):

- `NTASKS_LND`: 128-512 tasks
- `NTHRDS_LND`: 1-2 threads


For high resolution (ne120):

- `NTASKS_LND`: 1024-4096 tasks


### Multiple Instance Support

ELM supports running multiple instances simultaneously for ensemble simulations. This is controlled by `NINST_LND`  [driver-mct/shr/seq_comm_mct.F90 72](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/driver-mct/shr/seq_comm_mct.F90#L72-L72)

Multi-Instance Configuration:

- Each instance has independent atmospheric forcing (if using data atmosphere)
- Instances can have different initial conditions or parameter perturbations
- Useful for uncertainty quantification and data assimilation


Test example with multiple instances: `SMS_P12x2.ne4pg2_oQU480.WCYCL1850NS.allactive-mach_mods`  [cime_config/tests.py 273](https://github.com/jingtao-lbl/E3SM/blob/389f40b9/cime_config/tests.py#L273-L273)
