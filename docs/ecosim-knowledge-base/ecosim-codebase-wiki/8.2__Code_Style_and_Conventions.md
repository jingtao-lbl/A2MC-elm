## Purpose and Scope

This document establishes the coding standards, naming conventions, and organizational patterns used throughout the EcoSIM codebase. It serves as a reference for developers adding new features or modifying existing code to ensure consistency and maintainability. For guidance on implementing new biogeochemical processes, see [Adding New Process Models](#8.1) . For build system specifics, see [Build System Details](#8.3) .

## File Organization and Directory Structure

### Module Directory Layout

EcoSIM follows a hierarchical directory structure where each subdirectory under `f90src/` contains functionally-related modules. The build order is defined in [f90src/CMakeLists.txt 1-23](https://github.com/jingtao-lbl/EcoSIM/blob/7b8a4cf6/f90src/CMakeLists.txt#L1-L23) and reflects dependency relationships.

Sources:  [f90src/CMakeLists.txt 1-23](https://github.com/jingtao-lbl/EcoSIM/blob/7b8a4cf6/f90src/CMakeLists.txt#L1-L23)

### Directory Naming Conventions

| Directory Type | Pattern | Examples | 
| --- | --- | --- |
| Core utilities | Single word, capitalized | Utils, Mesh, Minimath | 
| Process models | Process name + _bgc suffix | Plant_bgc, Microbial_bgc | 
| Data structures | Descriptive + _datatype or Data | Ecosim_datatype, APIData | 
| Configuration | Descriptive + config or pars | Modelconfig, Modelpars | 
| Tools/utilities | Function + Tools or utils | DebugTools, IOutils, ATSUtils | 
| Interface layers | Uppercase acronym + Utils or plural | ATSUtils, APIs | 


Sources:  [f90src/CMakeLists.txt 1-23](https://github.com/jingtao-lbl/EcoSIM/blob/7b8a4cf6/f90src/CMakeLists.txt#L1-L23)

## Fortran Language Standards

### File Extensions

EcoSIM uses the `.F90` extension (capital F) for all Fortran source files. This extension enables C preprocessor directives before Fortran compilation.

| Extension | Usage | Preprocessing | 
| --- | --- | --- |
| .F90 | Primary source files | Yes (C preprocessor enabled) | 
| .f90 | Not used in EcoSIM | No preprocessing |

## Variable and Array Naming Conventions

### Dimensional Suffix Convention

EcoSIM uses a systematic suffix convention for multi-dimensional arrays to indicate their indexing dimensions:

| Suffix | Dimension | Description | 
| --- | --- | --- |
| _vr | Vertical layer | Soil layers, snow layers | 
| _pft | Plant functional type | Plant species/types | 
| _col | Column | Spatial grid columns | 
| _mic | Microbial guild | Microbial functional groups | 
| _dom | DOM pool | Dissolved organic matter pools |

## Code Documentation Standards

### Module-Level Documentation

Each module should begin with a comment block describing:

- **Purpose:**What the module does
- **Dependencies:**Major modules it depends on
- **Public interface:**Exposed subroutines and types
- **Author/Date:**Optional but recommended for major modules


### Subroutine Documentation

Each public subroutine should include:

- **Description:**Brief purpose statement
- **Arguments:**Intent (in/out/inout) and description
- **Side effects:**Module-level state changes
- **Notes:**Important implementation details
